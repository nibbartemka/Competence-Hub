# Competence Hub

**Competence Hub** - это веб-платформа для адаптивного контроля знаний и умений студентов. В основе системы лежит представление дисциплины в виде графа знаний: темы, элементы знаний и связи между ними формируют наглядную и управляемую структуру учебного материала. Такой подход позволяет использовать учебные данные не только как справочник, но и как основу для построения логики обучения, контроля и сопровождения индивидуального прогресса.

Проект ориентирован на сопровождение учебного процесса сразу с нескольких сторон. Преподаватель и эксперт могут работать со структурой дисциплины, уточнять зависимости между темами, формировать учебные траектории и подбирать задания. Студент получает последовательный маршрут освоения материала, проходит контроль по темам, отправляет решения и получает обратную связь по результатам выполнения.

Отдельная ценность системы в том, что она объединяет визуализацию и прикладную логику. Граф знаний помогает видеть предметную область как связанную систему, а механика траекторий и заданий переводит эту структуру в практический инструмент для адаптивного обучения. За счет этого платформа может использоваться и как среда проектирования дисциплины, и как рабочий интерфейс для сопровождения образовательного процесса.

С технической стороны проект состоит из `FastAPI` backend, `React + Vite` frontend и контейнерной инфраструктуры на базе `Docker Compose`. Для хранения и обслуживания данных используются `PostgreSQL`, `Redis`, `MinIO` и `Nginx`.

## Возможности системы

- визуализация графа знаний дисциплины;
- работа с темами, элементами знаний и связями между ними;
- построение и сопровождение учебных траекторий;
- назначение и прохождение заданий в рамках траектории;
- загрузка файловых решений и последующая проверка;
- разделение сценариев работы по ролям: студент, преподаватель, эксперт, администратор.

## Архитектура

Проект разворачивается как набор связанных сервисов:

- `backend` - API и основная бизнес-логика приложения;
- `frontend` - пользовательский интерфейс;
- `nginx` - единая точка входа в приложение;
- `postgres` - основная база данных;
- `redis` - вспомогательное хранилище для инфраструктурных сценариев;
- `minio` - объектное хранилище для файловых отправок и связанных материалов.

Такой состав сервисов позволяет локально поднять окружение, близкое к реальному рабочему контуру, без ручной настройки каждого компонента по отдельности.

## Запуск проекта

### 1. Подготовить файл окружения

Скопируйте шаблон переменных окружения и создайте локальный файл `.env`:

```powershell
cp .env.example .env
```

При необходимости после этого можно открыть `.env` и изменить значения под свое локальное окружение, но для базового запуска обычно достаточно значений из шаблона.

### 2. Собрать и запустить контейнеры

В корне проекта выполните команду:

```powershell
docker compose up --build -d
```

Эта команда:

- соберет backend, frontend и nginx-образы;
- поднимет контейнеры приложения и инфраструктурных сервисов;
- создаст необходимые тома для данных;
- запустит проект в фоновом режиме.

### 3. Открыть приложение

После успешного запуска будут доступны следующие адреса:

- `http://localhost:8080` - основной интерфейс системы;
- `http://localhost:8000/docs` - Swagger UI для backend API;
- `http://localhost:9001` - консоль `MinIO`, если требуется работа с объектным хранилищем.
